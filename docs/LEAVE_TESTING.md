# ทดสอบระบบลาใน Development

## เตรียมเครื่องและข้อมูล

1. Pull สาขา `feat/portal-ux`, รัน `npm ci`, สร้าง `.env.local` จาก `.env.example` และใส่ค่าของ Firebase **development** project
2. ตรวจว่าองค์กร `superjeew` และบริษัท SPJ01/SPJ02 เปิดใช้งาน บัญชีทดสอบมี employee record, companyId และ membership ที่ถูกต้อง
3. กำหนดวันทำงานของแต่ละบริษัทที่ `/manage/company/work-schedules` และตรวจวันหยุดที่ `/manage/leave/holidays`
4. กำหนด Leave Type, Template และมอบ Template ให้พนักงาน หรือใส่ยอดนำเข้าต้นรอบตามกรณีที่ต้องทดสอบ
5. สำหรับใบลาจริง ให้มีหัวหน้าผู้อนุมัติและบัญชี HR ที่เชื่อม employee; กรณีเกินสิทธิ์ต้องเป็นผู้อนุมัติ **คนละคน**

## ใช้ SUPERADMIN ทดสอบด้วยบัญชีเดียว

เพิ่ม `LEAVE_DEV_TEST_ENABLED=true` ใน `.env.local` เมื่อ Firebase Admin project ID ลงท้าย `-dev` หรือ `-test` และรัน `npm run dev` ด้วยบัญชี SUPERADMIN เปิด `/manage/leave/dev-test`

1. เลือกวัน SPJ01 จันทร์–ศุกร์ หรือ SPJ02 จันทร์–เสาร์ ใส่วันหยุดจำลองและสิทธิ์วันลา
2. สร้างใบลาที่ไม่เกินสิทธิ์ กดอนุมัติหรือปฏิเสธจากฝั่งหัวหน้า และตรวจยอด
3. สร้างใบลาที่เกินสิทธิ์ ลองอนุมัติจากหัวหน้าและ HR สลับลำดับ; HR ต้องเลือกการจัดการวันเกินและกรอกเหตุผล
4. ลองปฏิเสธจากฝ่ายใดฝ่ายหนึ่ง ตรวจว่าฝ่ายที่เหลือดำเนินการต่อไม่ได้
5. เปิดหน้าการแจ้งเตือนของบัญชีเดียวกัน และลบรายการทดสอบเพื่อตรวจยอดที่คืน

ข้อมูล Dev Test เก็บแยกที่ `leaveDevTestRuns`; ไม่สร้าง `leaveRequests` จริงและไม่เปลี่ยนยอดของพนักงานจริง ปิดได้ด้วย `LEAVE_DEV_TEST_ENABLED=false` หรือเมื่อรัน production

## ทดสอบวงจรจริงกับบัญชีทดสอบ

1. ลงชื่อเข้าบัญชี employee บันทึกฉบับร่างโดยลองขอเกินสิทธิ์ ฉบับร่างต้องไม่ตัดยอด
2. กดส่งใบลาภายในสิทธิ์ ตรวจสถานะรออนุมัติและยอดหลังกันใบที่รอ; ส่งวันทับกันอีกใบต้องถูกปฏิเสธ
3. ลงชื่อเข้าบัญชีหัวหน้า อนุมัติ แล้วตรวจใบลาและยอดคงเหลือของ employee
4. ส่งใบเกินสิทธิ์ แล้วให้หัวหน้าและ HR (คนละบัญชี) ตัดสินใจตามเงื่อนไข ตรวจกรณีอนุมัติทั้งสองฝ่ายและปฏิเสธหนึ่งฝ่าย
5. ตรวจ `/manage/leave/history` และการแจ้งเตือน; ใช้ ADMIN/SUPERADMIN ลบใบที่อนุมัติแล้วโดยระบุเหตุผล ตรวจว่าประวัติยังอยู่และยอดคืนตามจำนวนวันของใบที่ลบ
6. ตรวจวันหยุด วันเสาร์ของแต่ละบริษัท การลาครึ่งวัน ยอดนำเข้าก่อน/หลัง cutover และการขึ้นรอบปีใหม่

อย่าทดสอบลบกับข้อมูล production การทดสอบใน Dev Test ไม่ทดแทนขั้นตอนวงจรจริงข้างต้น ขณะนี้วันเริ่มรอบปีหลักยังคงเป็น 1 มกราคม
